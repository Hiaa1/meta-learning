# meta-learning

一个 Claude Code skill:**用"基底"组织解释和学习**。

核心命题一句话——

> 理解的骨架是**基底的位置**,不是知识的数量。任何时刻你有一个封死的基底、一个动手的工作层、一个看不见的下层;进阶 = 基底往下挪一格。

由此推出这个 skill 的第一条动作:**解释的第一句是声明这次钉在哪,不是给定义。** 定义说明一个词的意思;基底声明界定的是在回答哪个问题、哪些东西被暂时封住。只有后者能让人立刻动手。

目标不是让对方觉得听懂了,而是让对方**能动手,并且知道自己什么时候会错**。前者可以靠流畅的文字伪造,后者不能。

## 一次只推进一格

这是优先级最高的一条硬约束。**一格 = 一个主题,一个层级。**一次回复只走一格,然后停下来等你动手。

不是为了省篇幅,是为了**顺序**:下一格的内容要靠这一格产生的摩擦来定位。摩擦还没发生就往下讲,讲的是它猜的那一格,不是你实际卡住的那一格。

自检标准:**一次回复结束时,你手上应该是一个能立刻执行的动作,而不是一堆知识。**

## 四个模式

| 你在要什么 | 模式 | 做什么 |
|---|---|---|
| 理解一个具体机制 | A | 七块骨架:钉在哪 → 一句话机制 → 长出什么 → 边上是什么 → 什么时候会坏 → 去做一件事 → 升级钩子 |
| 进入一个领域,要整条路径 | B | 五级阶梯 **画 → 封 → 摸 → 换 → 挪**,每级有独立的错误征兆和升级判据 |
| 卡住了,"每层都对但就是不 work" | C | 分诊 → 先横后纵 → 补丁计数 → 进步/退化判定 → 靠失败图案定位 |
| 上一格搞定了,"然后呢" | D | 声明当前位置 → 从「横向铺开 / 纵向下挪 / 换主题 / 停」里选**一个**,默认横向 |

模式 A 之前还有一道闸:**问的是一个领域还是一个具体机制。**问领域说明还没有层图,那就只画层图然后停,不顺手解释里面任何一层。

## 三条最反直觉的规则

- **封区之内不加免责声明。** 不写"粗略地说""实际上更复杂"。这些话散在正文里等于从没封过基底,同时制造焦虑和瘫痪。所有不确定性集中到两处:封线,和失效征兆。
- **必须给可观察的失效征兆。** 给不出失效征兆的解释交付的是黑箱,不是接口。共识接口白送你基底的**内容**,它的**成立条件**和**失效征兆**是默会知识,靠事故和口传传播——那才是决定你会不会被烧到的部分。
- **横向邻居优先于纵深。** 初学者的错误和真实 bug 的分布一样,横向混淆占多数,不是挖得不够深。大多数教学材料完全省了这一块。
- **钩子响了不等于可以升级。** 别扭触发的是**复查**,升级判据才是**闸门**。好奇("下一层是什么")不算别扭。判据没满足就明说缺哪一条——跳过判据往下讲,结果是听得懂但干不了活,那比停在原地更差,因为它还让人误以为已经过关了。

```

references/
  ladder.md              # 模式 B/D:L0–L4 阶梯、三个常设物件、深度分配

```

`SKILL.md` 每次调用都加载;两个 reference 按模式**按需**加载。

## 适用边界

这套东西买的是**迁移能力**和**不被自己骗**,卖的是**速度**。

做研究划算;赶交付不划算,那时候正确动作是全部停在 L1。也不适用于读一段具体代码或查 API 签名。
